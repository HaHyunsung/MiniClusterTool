# 구현 가이드 01 — 운전 상태 모델 (Core)

작성일: 2026-10-03
관련 결정: ADR 0004(명령은 즉시 bool), ADR 0005(운전 상태 모델 채택과 C# 변경점)

> 2026-10-04 개정: 상태 전이는 상태머신이 Scan에서 스스로 한다. Complete()/SetActivity()는 삭제.
> 완료 조건 Permissive 5개 추가: AbortedCondition, HomedCondition, PausedCondition, StoppedCondition, RunningCondition(충족=Running, 미충족=Idle).
> 층 2가 생성자에서 람다로 조건 등록. 조건이 비어 있으면 즉시 완료(TcHit 조건 배열 TRUE 초기화와 동일). 자동 전이는 에러와 무관하게 진행(2026-10-04 개발자 결정). 에러는 새 명령(Home/Run/SemiAuto) 거부로만 작동.
> 최신 내용은 HTML 가이드(claude.ai 아티팩트 "운전 상태 모델 구현 가이드")가 기준이다.

이 문서의 사용법
AI가 무엇을 만들지, 각 클래스의 모습(멤버와 시그니처), 쓰인 C# 개념을 정한다.
메서드 본문은 개발자가 작성한다. Home()만 예시로 전체를 보여주고, 나머지는 같은 패턴으로 채운다.
막히면 "어느 파일, 어느 메서드, 어디서 막혔는지"로 물어본다.


## 1. 지금까지 정해진 것

상태머신은 운전 상태 하나다. TcHit FB_StateMachine(PackML 축약형)의 상태 집합과 명령 수락 규칙을 그대로 따른다.
진공 같은 챔버 상태는 상태머신이 아니라 챔버의 속성이고 Cluster 쪽에 둔다.
명령은 즉시 bool을 반환한다. 완료는 상태로 본다.
C#에서는 상속 한 덩어리 대신 두 층으로 나눈다.
  층 1. 순수 상태 모델: 상태, 명령 수락, 전이, 이력, 타임아웃. 장치도 시퀀스도 모른다. ← 이번 작업
  층 2. 모듈 베이스: 층 1을 들고 Aborting/Homing/Running 시퀀스를 채우고, 하위 상태를 보고 완료를 판정한다. ← 다음 작업

층 1만 따로 두는 이유
수락 규칙표 전체를 장치 없이 테스트할 수 있다. 사양서 5.4 요구(불허 전이 거부, 전이 타임아웃, 이력, 장치 없이 테스트)가 전부 이 층에 걸린다.
TcHit에서는 "완료 판정"이 FB_StateMachine 안의 CheckStatus에 있었다. 여기서는 완료 판정을 층 2로 빼고, 층 1은 "완료됐다"는 통보만 받는다(Complete()).
그래서 층 1은 조건 배열을 갖지 않는다. 조건 배열의 역할은 층 2가 Permissive로 한다.

## 3. enum 세 개

```csharp
public enum OperationState
{
    None = 0,      // 전원 투입 직후. Abort만 받는다
    Aborting, Aborted,
    Homing, Homed,
    Idle, Running,
    Pausing, Paused,
    Stopping, Stopped,
    SemiAuto
}

public enum OperationMode { None = 0, Manual, Maint, Auto }

public enum OperationErrorCode { None = 0, AbortingTimeout, HomingTimeout, PausingTimeout, StoppingTimeout }
```

TcHit과 다른 점
LAST는 뺀다. PLC에서 배열 크기나 범위 검사용으로 쓰던 것인데 C#에서는 Enum.GetValues로 해결되어 필요 없다.
값은 None만 0으로 지정하고 나머지는 자동 증가로 둔다. DB에 숫자로 저장하게 되면 그때 명시적으로 번호를 박는다.
ErrorReset은 상태 전이가 아니므로 명령 enum을 따로 두지 않는다. Reset()은 메서드로만 있다.


## 4. ModeSelector — 모드를 객체로 빼는 이유

```csharp
public class ModeSelector
{
    #region Fields
    private readonly List<OperationStateMachine> members = new();   // 이 모드를 따르는 상태머신들
    #endregion

    #region Properties
    public OperationMode Current { get; private set; }
    public Permissive ManualPermissive { get; }   // 모드별 추가 조건. 고정 규칙에 AND로만 붙는다
    public Permissive MaintPermissive { get; }
    public Permissive AutoPermissive { get; }
    #endregion

    #region Constructor
    public ModeSelector(OperationMode initMode)
    #endregion

    #region Methods
    internal void Attach(OperationStateMachine member)   // 상태머신 생성자가 자기 자신을 등록. 이미 있으면 무시
    public bool Change(OperationMode target)             // 고정 규칙 AND target의 Permissive 통과 시 변경, true
    #endregion
}
```

참조 공유: ModeSelector 하나를 여러 상태머신에 넘기면 모두 같은 객체를 본다(REFERENCE TO와 같음). FollowMode 복사가 필요 없다.

모드 변경 규칙은 프레임워크에 고정한다 (안전 관련이라 장비마다 달라지면 안 된다). 장비는 모드별 Permissive(Manual/Maint/AutoPermissive)로 더 엄격하게만 할 수 있다. 가는 모드마다 필요한 조건이 달라서 모드별로 둔다(2026-10-04).
Manual: Attach된 전원이 Aborted 또는 Aborting (Aborting 고착 시 탈출구)
Maint, Auto: 전원이 Aborted 또는 Homed
None: 항상 거부. 같은 모드: true만 반환.
하위 전원 StandStill 조건은 층 2가 생기면 같은 자리에 고정 규칙으로 추가한다.

등록은 OperationStateMachine 생성자가 mode.Attach(this)로 직접 한다. 바깥 조립 코드에 맡기면 빠뜨릴 수 있다(ADR 0003과 같은 이유).
internal: 같은 어셈블리(FabStack.Core) 안에서만 호출 가능. 장비 코드가 상태머신을 임의로 끼워 넣지 못하게 막는다. 테스트에서는 생성 시 자동 호출되므로 직접 부를 일이 없다.


## 5. record 두 개 — 이력과 타임아웃

```csharp
public enum TransitionTrigger { Abort, Home, Run, Pause, Stop, SemiAuto, Complete, Activity }

public sealed record StateTransition(DateTimeOffset Time, OperationState From, OperationState To, TransitionTrigger Trigger);

public sealed record TransitionTimeouts(TimeSpan Aborting, TimeSpan? Homing = null, TimeSpan? Pausing = null, TimeSpan? Stopping = null);
```

타임아웃은 전이마다 주인이 다르다 (2026-10-03 개발자 지적 반영)
Aborting: 몇 초 이내가 정상 → 층 1이 감시(필수 값).
Homing: Home 시퀀스 길이에 따라 다름 → 각 스텝의 장치 타임아웃이 주인. 층 1은 선택(전체 상한 백업).
Pausing: 진행 중 동작이 끝날 때까지 → 그 장치의 타임아웃. 층 1은 선택.
Stopping: 사이클 스톱이라 공정 종료까지 → 공정/레시피 타임아웃. 층 1은 보통 null.
TimeSpan?는 null 허용 값 타입, = null은 매개변수 기본값. Scan은 해당 값이 null이면 감시하지 않는다.

C# 개념: record
값을 묶어 두는 불변 데이터 타입이다. PLC의 STRUCT에 가깝지만 한 번 만들면 값을 바꿀 수 없다.
위처럼 괄호 안에 쓰는 형태(위치 record)는 생성자, 읽기 전용 프로퍼티, 값 비교(==)를 컴파일러가 자동으로 만들어 준다.
  생성: var t = new StateTransition(clock.Now, OperationState.Aborted, OperationState.Homing, TransitionTrigger.Home);
  읽기: t.From, t.To
이력에 record를 쓰는 이유: 이력은 한 번 기록되면 바뀌면 안 된다. 불변이 그걸 타입으로 보장한다.
테스트에서도 Assert.Equal(expected, actual)로 record 두 개를 통째로 비교할 수 있다(값 비교라서).
sealed는 상속 금지라는 뜻이다. 데이터 타입은 상속할 일이 없으니 막아 둔다(Permissive도 sealed).

Permissive 안의 private sealed record Condition(...)이 이미 같은 문법이다. 그걸 public으로 쓴다고 보면 된다.


## 6. OperationStateMachine — 본체

모습

```csharp
public class OperationStateMachine
{
    #region Fields
    private readonly ModeSelector mode;
    private readonly TransitionTimeouts timeouts;
    private readonly IClock clock;                 // 이력 시각용. 아래 설명 참고
    private readonly OnDelayTimer timer;           // 전이 상태 진입 시각 (TON)
    private readonly List<StateTransition> history = new();
    #endregion

    #region Properties
    public string Name { get; }
    public OperationState State { get; private set; } = OperationState.None;
    public bool Resumed { get; private set; }      // PAUSED에서 Run으로 들어왔는가 (TcHit P_Resumed)
    public bool Error { get; private set; }
    public int ErrorID { get; private set; }

    public Permissive HomePermissive { get; }      // 층 2가 추가 조건(하위 에러 없음, 하위 전원 ABORTED 등)을 등록
    public Permissive RunPermissive { get; }
    public Permissive SemiAutoPermissive { get; }

    public IReadOnlyList<StateTransition> History => history;
    #endregion

    #region Constructor
    public OperationStateMachine(string name, ModeSelector mode, TransitionTimeouts timeouts, IClock clock, IScanCycle scanCycle)
    // 필드/프로퍼티 대입, Permissive 3개 new, timer = new OnDelayTimer(clock)
    // mode.Attach(this);
    // 마지막 줄: scanCycle.Register(Scan);
    #endregion

    #region Methods
    public bool Abort()
    public bool Home()
    public bool Run()
    public bool Pause()
    public bool Stop()
    public bool SemiAuto()
    public bool Complete()                  // 전이 상태 → 고정 상태. 층 2가 완료 판정 후 부른다
    public bool SetActivity(bool working)   // Idle ⇄ Running. 층 2가 일감 유무로 부른다
    public void Reset()

    private void ChangeState(OperationState next, TransitionTrigger trigger)
    private void Scan()                      // 전이 상태 타임아웃 감시만
    #endregion
}
```

예시: Home() 전체

```csharp
public bool Home()
{
    if (State != OperationState.Aborted) return false;
    if (mode.Current is not (OperationMode.Maint or OperationMode.Auto)) return false;
    if (Error || !HomePermissive.IsAllowed) return false;

    ChangeState(OperationState.Homing, TransitionTrigger.Home);
    return true;
}
```

모든 명령이 이 순서를 따른다. 상태 확인 → 모드 확인 → 에러/Permissive 확인 → ChangeState → true.
조건은 아래 7절 표를 그대로 옮기면 된다.

ChangeState가 할 일 (직접 작성)
1. history에 new StateTransition(clock.Now, State, next, trigger) 추가
2. State = next
3. next가 전이 상태(Aborting, Homing, Pausing, Stopping)면 timer.Tick(), 아니면 timer.Stop()
상태를 바꾸는 곳은 ChangeState 한 곳뿐이다. State에 직접 대입하는 코드가 다른 메서드에 있으면 이력이 빠진다.
FakeValve에서 "시간 판단은 Scan 한 곳"으로 정한 것과 같은 이유다. 한 곳으로 모아야 빠짐이 없다.

Scan이 할 일 (직접 작성)
전이 상태에서 timer.ElapsedTime()이 timeouts의 해당 값 이상이면 Error = true, ErrorID = 해당 코드.
상태는 바꾸지 않는다. TcHit처럼 에러에 대한 대응(Abort 호출)은 층 2 시퀀스의 몫이다.
이미 Error면 아무것도 하지 않는다(최초 원인 유지, ADR 0002와 같은 규칙).

Reset이 할 일
Error = false, ErrorID = 0.
지금 전이 상태라면 timer.Tick()으로 타이머를 다시 시작한다. 안 하면 다음 스캔에서 경과 시간이 이미 초과라 즉시 다시 에러가 선다.

C# 개념 몇 가지

is not (A or B) 패턴
mode.Current is not (OperationMode.Maint or OperationMode.Auto) 는 (mode.Current != Maint && mode.Current != Auto)와 같다.
C# 9부터 들어온 패턴 문법이다. 상태가 여러 개 중 하나인지 볼 일이 계속 나오므로 이걸 쓴다.
  if (State is OperationState.Running or OperationState.Idle) ...

switch 식 (Scan에서 타임아웃 값 고를 때 쓰면 깔끔하다)
  TimeSpan limit = State switch
  {
      OperationState.Homing => timeouts.Homing,
      ...
      _ => TimeSpan.MaxValue      // 전이 상태가 아니면 감시 안 함
  };
CASE문에 결과값이 있는 형태라고 보면 된다. _ 는 ELSE다.

IReadOnlyList와 private List
내부에서는 List(추가 가능)를 들고, 밖으로는 IReadOnlyList(읽기만)로 내보낸다.
PLC로 치면 내부 VAR는 FB 안에서만 쓰고, 밖에는 VAR_OUTPUT으로만 보여주는 것과 같다.
=> 는 "이 프로퍼티는 이 값을 돌려준다"는 짧은 문법이다. History => history; 는 get { return history; } 와 같다.

{ get; private set; }
밖에서는 읽기만, 클래스 안에서만 쓰기. 밸브 State와 같은 방식이다.

clock을 필드로 들고 있는 이유
부품(밸브, 펌프)은 clock을 타이머에 넘기기만 하고 필드로 들지 않기로 했다(05 문서).
여기서는 이력에 시각을 찍어야 해서 clock.Now가 필요하다. 그래서 예외로 필드로 든다.


## 7. 수락 규칙표 (TcHit 2.0 README 기준)

명령        허용 상태                         모드          그 외                    결과
Abort       어느 상태든                       무관          Aborting 중이면 true만 반환(타이머 재시작 안 함)   Aborting
Home        Aborted                           Maint, Auto   NOT Error, HomePermissive    Homing
Run         Homed, Stopped, Paused            Auto          NOT Error, RunPermissive     Idle (Paused에서 왔으면 Resumed = true, 아니면 false)
Pause       Running, Idle                     Auto          -                            Pausing
Stop        Running, Idle                     Auto          -                            Stopping
SemiAuto    Homed                             Maint         NOT Error, SemiAutoPermissive  SemiAuto (빠져나오는 길은 Abort뿐)

Complete    Aborting→Aborted, Homing→Homed, Pausing→Paused, Stopping→Stopped. 그 외 상태에서는 false.
SetActivity Idle에서 true면 Running, Running에서 false면 Idle. 같은 값이면 true만 반환(이력 안 남김). Idle/Running이 아니면 false.

거부 규칙: 조건에 안 맞으면 false. 상태는 바뀌지 않고 이력도 남지 않는다.
사양서 5.4의 "조용히 무시하면 안 된다"는 false 반환으로 충족한다. 거부 사유를 구조화해서 돌려줄지는 Result 타입 결정(사양서 6.6) 때 다시 본다.

None 상태: Abort만 받는다. 위 표에서 None이 허용 상태에 없는 명령은 전부 false가 되므로 따로 코드를 쓸 필요 없다.


## 8. 테스트 (OperationStateMachineTests.cs)

구성은 FakeValveTests와 같다. 생성자에서 FakeClock, FakeScanCycle(10ms), ModeSelector, 상태머신을 만든다.
타임아웃은 짧게 준다. 예: new TransitionTimeouts(Aborting: 1초, Homing: 1초)  (Pausing, Stopping 생략 = null)
(TimeSpan.FromSeconds(1). 위치 record도 이렇게 이름을 붙여 넘길 수 있다.)

최소 목록
1. 초기 상태는 None이고, None에서 Home은 거부된다
2. Abort → Aborting, Complete → Aborted
3. Manual 모드에서 Aborted 상태의 Home은 거부된다
4. Maint 모드에서 Home → Homing, Complete → Homed
5. Maint 모드에서 Homed 상태의 Run은 거부된다 (Auto만 허용)
6. Auto에서 Run → Idle, SetActivity(true) → Running, Pause → Pausing, Complete → Paused, Run → Idle이고 Resumed = true
7. Aborting 중 타임아웃이 지나면 Error = true, ErrorID = AbortingTimeout, 상태는 Aborting 유지
8. 에러 중 Home은 거부되고, Abort는 수락된다
9. Reset 후 Error = false, 다음 스캔에서 바로 다시 에러가 서지 않는다
10. HomePermissive에 false 조건을 등록하면 Home이 거부된다
11. 이력: Abort → Complete → Home 후 History.Count == 3이고, 마지막 항목의 From/To/Trigger가 맞다
12. 거부된 명령은 이력을 남기지 않는다
13. 같은 ModeSelector를 쓰는 상태머신 중 하나라도 Running이면 Maint 변경 거부
14. 둘 다 Aborted면 Manual → Maint 수락, 둘 다 바뀐 모드를 본다
15. AutoPermissive에 false 조건이 있으면 Auto 변경은 거부, Maint 변경은 수락
16. Stopping 타임아웃이 null이면 오래 머물러도 에러가 서지 않는다
테스트 모드는 new ModeSelector(OperationMode.Auto)처럼 생성자에서 정한다. 초기 None 상태에서는 Change가 고정 규칙에 걸려 거부된다.

테스트 이름은 무엇을 검증하는지 읽히게 쓴다. 예: Home_InManualMode_IsRejected


## 9. 이번에 일부러 뺀 것

상태 변경 이벤트(event). UI나 로그가 상태 변화를 받아야 할 때 추가한다. 지금 넣으면 스레드 문제가 같이 따라온다.
명령 스레드와 Scan 스레드의 동시 접근. 실행용 스캔 사이클(Infrastructure)을 만들 때 lock 하나로 처리한다(ADR 0005).
이력 개수 제한. 지금은 무한히 쌓인다. DB/로그 저장이 생기면 정한다.
하위 집계(에러 합산, 하위 StandStill 판정, 명령 전파). 층 2의 일이다.
Reset 이름. TcHit 2.0은 ErrorReset이지만 지금 장치들이 Reset()이라 맞춰 둔다. 기능별 인터페이스(ErrorReset/StandStill/Abortable 계열)를 만들 때 한 번에 바꾼다.
