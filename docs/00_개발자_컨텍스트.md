# 개발자 컨텍스트

이 문서는 이 프로젝트를 왜 하는지, 무엇을 얻으려 하는지를 담는다.
AI가 조언의 수위와 방향을 정할 때 기준으로 삼는다.


## 1. 개발자 배경

이름: 하현성
경력: 자동화 장비 제어 소프트웨어 개발 약 10년
소속: 18명 규모의 장비 회사. 여러 역할을 겸하는 구조
현재 위치: TwinCAT / C# 분야 실무 메인 담당
학력: 마이스터고 졸업 후 바로 취업, 현재 아주대 융합시스템공학과(재직자전형) 졸업까지 약 1년

주력 스택: Beckhoff TwinCAT, C#
경험 산업군: 반도체, 이차전지, 디스플레이, 항공, 물류 자동화


## 2. 검증된 강점

이 항목들은 이미 갖췄으므로 학습 대상이 아니다.

- 실장비 도메인 이해. 진공, 반송, 인터락, 시퀀스의 현실적 제약을 안다.
- 클러스터 툴(PEALD, THALD, Load Lock, TM) 제어 시스템 단독 완주 경험.
- SECS/GEM 실사용. xcom과 SECS-II로 Wafer Loading 시스템 구현. 스트림 펑션 10개 수준.
- 사수와 레퍼런스 없이 문제를 끝까지 끌고 가는 자기주도성.
- 실시간 제약과 하드웨어 타이밍에 대한 감각.

AI는 이 영역에서 기초 설명을 늘어놓지 않는다. 아는 것을 다시 가르치면 시간 낭비다.


## 3. 목표

1순위는 더 큰 장비사로의 경력 이직이다. 직종 전환이 아니다.
쌓아온 FA 경력을 버리지 않되, 그 위에 상위 소프트웨어 설계 역량을 얹는 것이 방향이다.

2순위로 IT 직군 전환 가능성을 열어두고 있으나 확정된 선택은 아니다.

따라서 이 프로젝트는 FA 도메인을 그대로 활용한다.
도메인을 버리고 웹 서비스를 만드는 방향은 목표 대비 효율이 낮다고 판단해 배제했다.


## 4. 역량 갭 평가

문제는 개별 기술의 부재가 아니다.
"설계 판단을 스스로 내리고 그것을 남에게 검증받은 경험이 없다"는 하나의 원인에서 갈라져 나온 증상들이다.

### 4.1 추상화 경계를 그어본 적이 없음
인터페이스를 개념만 알고 실무에서 써본 적이 없다.
상속, 싱글턴, 객체 분리는 하지만 구현체에 직접 의존하는 구조다.
회사 프레임워크 위에서 장비를 만드는 소비자 역할이었고, 프레임워크 자체를 설계한 경험은 없다.

### 4.2 테스트 부재
4.1의 뒷면이다. 인터페이스가 없으니 장비 없이 로직만 검증할 방법이 없었다.
결과적으로 검증은 항상 현장 실물로 이뤄졌고, 이는 출장 기간을 늘리는 구조적 원인이기도 하다.

### 4.3 C# 공백
메인 언어가 TwinCAT으로 옮겨간 지 약 5년.
그 사이 바뀐 생태계를 따라가지 못했다. async/await 기반 동시성, DI 컨테이너, nullable reference types, record, 최신 LINQ, .NET 8 런타임.
스레드는 사용할 수 있으나 누수 없이 다룬다고 자신하지 못하는 상태다.

### 4.4 계층 분리 경험 부재
프론트엔드와 백엔드를 나눠 개발해본 적이 없다.
UI, 도메인 로직, 통신, 영속성을 각각 다른 책임으로 떼어본 경험이 없다.

### 4.5 DB 설계 경험 부재
이미 구축된 DB에 붙어 LOT 정보를 조회하는 수준의 SQL과 DB 정의서 작성 경험.
스키마를 직접 설계하고 구축한 적은 없다.

### 4.6 협업 방식 부재
Git은 commit/push/pull 수준의 단독 관리.
브랜치 전략, 코드리뷰, PR 경험이 없고 수동 비교로 병합해 왔다.
혼자 일하는 것을 선호하며 인원 관리나 대형 프로젝트 리딩 경험이 약하다.

### 4.7 검증받지 못한 학습 경로
사수나 레퍼런스 없이 AI와 고객사 문의에 의존해 독학해 왔다.
방향이 제대로 된 것인지 외부에서 검증받은 적이 없다는 점을 본인이 우려하고 있다.
AI는 이 점을 특히 유념한다. 틀린 판단을 승인해주면 이 우려가 현실이 된다.


## 5. 이번 프로젝트에서 다루지 않는 것

우선순위가 낮다고 판단해 의도적으로 제외한 항목들이다.
AI는 이 방향으로 프로젝트를 확장하자고 제안하지 않는다.

- 웹 프론트엔드 프레임워크
- C / C++
- 래더 프로그래밍 (상위 SW로 가려는 방향과 반대)
- 대형 프로젝트 리딩 (개인 프로젝트로 만들 수 없는 종류)
- SECS/GEM (이미 실무 경험이 있어 새로 얻을 것이 적음)
- 어학 성적 (프로젝트로 메울 수 없어 별도 트랙으로 관리)


## 6. 학습 원칙

이 프로젝트가 속한 학습 공간의 원칙은 다음과 같다.

객체지향 개발자로서 부족한 부분을 보충하고 잃어버린 C# 감각을 되찾는 것이 목적이다.
따라서 AI에 의존해 모든 부분을 코딩하는 것을 지양한다.
막히는 부분은 AI에게 질문하되 실제 구현은 개발자가 직접한다.
